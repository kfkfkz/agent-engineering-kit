> **可选阶段文档**——概要设计的功能点含界面三件套（界面/前端展示清单/原型
> 引用）时启用；前提：概要设计已冻结。产物是可追踪、可实现、可验证的界面设计，

> 不适用项写"不适用 + 原因"，不删节。UI 无影响时说明 N/A 并跳过截图/原型流程。

## 原型确认记录

> 每个 PAGE/AREA 的确认记录绑定本地自包含 HTML 原始字节 SHA-256、当前设计体系与 UI-EV/权限上下文依赖摘要。维护者对实际预览明确回复后，才将决定人和 `confirmation_source: maintainer_reply` 写入此块；随后维护者还须在交互终端运行 `doc-gate prototype-confirm <需求目录> --page PAGE-1 --area AREA-1 --reviewer <姓名>` 并输入原型与当前依赖联合摘要的确认短语，生成不可覆盖的本地流程凭证。此凭证不认证操作系统用户身份，也不是数字签名。非交互/管道调用不能确认。原型预览必须使用静态 HTML/CSS；当前门禁拒绝脚本执行和外部/相对资源。`doc-gate --stage UI设计` 和阶段状态复验会重新打开原型、截图索引及确认凭证并核对摘要；任何内容或依赖变化均使受影响 PAGE/AREA 回到 DRAFT。

## 验证清单

- [ ] 页面/关键状态与 F/A 完成映射并去重；未覆盖项、N/A 原因和待确认上下文明确
- [ ] `截图索引.json` 中路径、权限、版本/视口、来源与摘要正确；空占位仍为 pending，截图默认不自动纳入 Git
- [ ] 每个被使用的 UI-EV 已先通过技术校验，再对目标权限/数据上下文逐项视觉核实；共享布局不继承权限结论
- [ ] 每个原型区域均可由 AREA-ID 反查 UI-EV、截图摘要、F/A、变更意图及实际依赖
- [ ] HTML 原型为批准根目录内的自包含单文件；预览和冻结复验拒绝路径穿越、符号链接及外部/相对资源
- [ ] HTML 原型与所引用截图均可预览；新增/修改/未知区域和偏差可见
- [ ] 维护者对实际预览明确给出 `ACCEPTED / NEEDS_REVISION / BLOCKED`；仅摘要及依赖仍匹配的 ACCEPTED 可成为基线
- [ ] 截图、需求、权限上下文、设计体系、共享布局或 Design Token 变化只使依赖关系可达的原型区域及确认失效，无关区域保持有效
- [ ] 展示清单与 API设计的接口字段一一对应
