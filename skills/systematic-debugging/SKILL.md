# 系统化诊断

Claude Code 使用 `/systematic-debugging`，Codex 使用 `$systematic-debugging`。

第一次结构检索必须先用 `codebase-memory`，沿当前工作树的实际调用链和 coverage 回到源码。日志、字面量和缺口做定向查找。

1. 对照期望和实际行为，复现或取得原问题的可复核证据，沿直接调用链找到问题起点。复用仍有效的证据，用最小实验验证根因。根因已证实且直接影响明确时进入方案交付。仍未知时报告已证实事实及证据缺口。
2. 在对话或现有任务记录给出根因及依据、最小修复与影响范围、回归方式。默认等待用户确认方案后再修改代码或配置。仅排查时交付诊断和建议。已确认本轮方案或明确授权直接修复时即可实施。
3. 按确认的范围定向修复，复跑原失败场景和相关回归。方案实质超出已确认范围时再次确认。

同类疑点留作线索，用户明确要求泛化查询后再验证。同一失败反复出现且没有新证据时停下，保留失败现场和未决假设。涉及公共契约或架构的处置回到 `repo-delivery`。
