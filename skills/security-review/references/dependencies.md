# 依赖采用与交付复验

本文件对应 Catalog ID `security-dependencies`。按本次拟依赖及真实影响范围取证；没有拟依赖且可信
scope producer 完整证明无依赖影响时，复用有效证据并结束。作者的空数组、needs_check=false 或没有
import 不证明无需检查。生产、测试、provided 和构建作用域分别保留。

## 设计采用前置

在现有概要取舍、详细设计或 Bounded 的已有决策载体记录：准确生态/包/拟版本、用途和作用域；适用
公告核验（来源、时点、覆盖、版本匹配及摘要）；环境/API/框架兼容依据；当前已知风险处置和来源。
版本未知、匹配不可靠、来源未核验、公告过期或审批未完成时 PENDING，提交本阶段设计评审的未决项。
这些前置不能以“上线前再扫”延期。明确违反当前策略为 REJECTED；必要证明齐备才 ADOPTABLE，
仅针对当前对象与声明范围，不称“绝无漏洞”。

公告身份可为 CVE/GHSA/OSV/厂商标识；无 CVE 不丢弃。别名合并须有可核验映射，不靠同标题。
消费成熟 SCA 或可靠适用公告的版本匹配证据，不自建所有生态比较器。公告 URL 是引用而非联网许可。
公告核验时点必须真实、带时区且非未来；默认年龄上限七天，受控项目政策可显式调整。请求数据不能
覆盖政策。缺工具时可用等效可靠公告证据；缺任何可靠来源保持 PENDING。

## 独立后补

实际解析/产物尚未生成可独立列 `pending_delivery_requirements`：所需清单、对象范围、验证及产物摘要。
交付时区分 PROPOSED/RESOLVED/SHIPPED，取得真实当前版本、直接/传递关系及引入链；BOM/父依赖/
仲裁、私有库、provided/test/插件、循环或超限不能覆盖的部分标缺口，不说全量树。
有发布物则核验真实 SHIPPED 清单；无发布物需可信不适用依据，不制造假包。声明新版但旧 JAR 残留
仍不能核验解决。

修复选升级兼容修复版、移除、替换或明确缓解；不自动跳大版本。保留无修复版的风险处置。复扫当前
公告并做适用构建/正常业务回归；漏洞消失但升级不兼容仍失败。已知受影响依赖不因无 import、无
可见调用链或无法复现 PoC 消失；reachability 独立表示 UNKNOWN/未观察/使用/已核验调用，并附范围证据。
来源、提案、政策、代码、公告库、解析或产物摘要变化时定向失效，仅复用仍适用的必要组件。
