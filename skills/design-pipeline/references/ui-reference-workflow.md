# UI 取证与原型

仅在本轮计划有 UI 影响时读取。用需求、页面和验收定位本次变化。先明确要保留的区域、关键交互状态和权限上下文，再列最小截图清单。共享布局可去重，不同权限和数据可见性分别核实。

1. 确认组件体系、版本和主题。缺事实时先用 `codebase-memory` 找前端入口，补读实际依赖、配置和设计令牌。记录可核对来源，待确认值保留 unknown。
2. 用受管 UI helper 从 UTF-8 JSON 创建占位和 `截图索引.json`，通知用户明确目录、短文件名、状态、采集权限、版本、视口及脱敏要求。新布局统一用 `--package-ref <仓库相对包路径>`。旧 `003-中文需求名称` 用 `change_id: "CHG-003"` 和对应单级 `requirement_dir`。
3. 用户替换后用同一定位参数运行 `validate`。只有实际看过且适用的截图才能通过 `record-review` 记录视觉结论，用当前索引 SHA 做 CAS。逐个 `applies_to` 确认格式、当前性和视觉适用。必要截图缺失或不适用时让维护者补证，阻断依赖该截图的区域。
4. 有可复用观察时只取本次区域；需要新增观察时用 [截图观察工作流](screenshot-observation-workflow.md)，缺正文再按 [提取契约](screenshot-observation.md) 读取当前截图。观察是设计证据之一，视觉与人工确认仍用原工作流。旧安装缺入口时将观察保留为候选。
5. 以 ArtifactPlan 批准的真实来源根保存原型。静态 schema1/2 用自包含 HTML，需要脚本时用 schema3 并由可信宿主执行固定交互序列。逐页及区域绑定 F/A、权限、截图、设计体系及实际依赖，用 `bind-prototype` 写反向追踪。涉及组件、布局或设计令牌依赖时使用 [源码区域基线](ui-source-baseline.md)。
6. 在 [原型确认工作流](prototype-confirmation-workflow.md) 中展示当前预览及引用截图，由维护者在终端作决定。交互原型同时核验可信运行观察。Gate 按实际字节与依赖摘要验证，依赖变化只影响相关消费者。

截图的 Git 检查为只读。分别报告 `git_status` 与 `git_staging`，已有暂存或跟踪时提示。Git 不可用或非仓库时保留 unknown。保留用户的 Git 配置和索引，原始截图按授权留在本机。
