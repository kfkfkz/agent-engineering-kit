对当前会话执行记忆捕获。触发时机：用户口头要求（"记一下/记住这个/沉淀一下"等），或任务收尾（功能验收通过、bug 修复完成）。

## 定位目标仓库

先解析本 `SKILL.md` 的真实路径（跟随符号链接），将技能目录向上三级作为目标仓库根目录；确认该目录同时包含 `.repo-memory-kit/manifest.json` 与 `docs/memory/RULES.md`。后续所有相对路径和命令均以该目标仓库为准，不以 Codex 的 workspace/CWD 为准。若校验失败，再使用用户明确指定的仓库；仍无法唯一定位时先询问，禁止写入猜测的目录。

**流程与规则的唯一来源：`docs/memory/RULES.md`「触发与捕获」与「条目格式」两节**——按候选提取 → 分类起草 → 呈现确认 → 入库 → 后续提示逐步执行。要点：

- 草稿必须带 **frontmatter**（type/status/created 必填，playbook 还须 verified；符号锚点写进 `anchors`，索引一句话写进 `summary`）——状态与日期不再写在正文。
- **业务流总结登记到业务域地图**：项目已有业务域地图（或 SDD 等体系，按建议格式组织、非事实权威）时，开发完/测试完的业务流（含跨域端到端链路）、能力入口、调用链、域职责类候选路由为域地图条目的新建/更新建议（待人确认），不在 playbook 里复制口径；playbook 只留场景化操作（环境访问、测试数据、环境执行套路、构建与工具操作）；事实以代码为准，与代码冲突时修正域地图。
- 入库到**对应模块目录**（`docs/memory/<模块>/`，模块按接口入口所属业务域划分、以业务域地图登记为准；存量类型目录条目可先 `memory-build --migrate-to-modules` 迁移）。
- 入库后**必须运行** `.repo-memory-kit/bin/memory-build` 刷新本地索引与 `.anchors.json`（`.repo-memory-kit/` 下的生成物，禁止手改）；zvec 可用时语义索引随动刷新。

## 边界（固定约束）

- **用户确认是入库的必要条件**：未确认的草稿不入库、不写入任何文件。
- 不捕获凭证、内网地址、真实 PII；不确定是否敏感时先问用户。
- L3 证据按分区处理：稳定约定须 ≥2 个独立 confirmed 来源；风险域单源可标「待观察」；证据充分的单次失败/明确否决决定可进入反模式。达到 L3 门槛（有效 confirmed 条目 ≥ 10，由 `memory-build` 自动判断）时只提示，蒸馏另行执行。
