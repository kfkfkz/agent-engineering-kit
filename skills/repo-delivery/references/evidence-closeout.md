# 证据与收口

本文件是 `repo-delivery.evidence.closeout` 的唯一权威，所有路线在交付前完整读取。

## 交付门禁

把当前 Route Card、写入前范围快照、基线、实际变更和已有验证交给 `delivery-gate`。范围、治理、独立评审与回执的规则由该入口执行一次，复用身份仍有效的证据。

对照写入前确定的验收条件和必须保持的行为，用实际 diff 和验证结果逐项核对。范围、契约或风险漂移按原确认边界处理，保存用户已确认的增量后再继续改动。实际偏离原范围或归属未明时保留阻塞。

## 文档、计划与记忆

- 将实现结果整合回既有 spec/SDD/版本文档；清除失效口径，不创建平行事实源。
- 有冻结计划时，执行期只更新执行记录与勾选状态。执行前计划基线与 `doc-gate closeout` 由
  [交付门禁](../../delivery-gate/SKILL.md) 核验。
- 检查现有记忆是否受影响，需要时运行 `memory-check`；新记忆先通过 `memory-capture` 展示候选，
  用户确认后才能写入和重建索引。
- 中断或跨会话转交用 `task-handoff`，不得只留一条无证据的“继续实现”。
- 文档复审回到 [设计流水线](../../design-pipeline/SKILL.md) 的当前评审状态，保留原 Issue 与轮次。

## 最终结论

沿用交付门禁结论，报告交付内容、验证证据、人工门禁和残余风险。Beta/advisory 状态单独披露，不得改变 Core release verdict。
